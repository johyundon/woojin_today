### 1. 지도교수 상담 - 로그인 (T-WIN 로그인)
- **메서드/주소**: `POST https://together.daejin.ac.kr/login/a/n/loginProc.do`
- **요청 헤더**:
  ```
  Content-Type: application/x-www-form-urlencoded; charset=UTF-8
  Origin: https://together.daejin.ac.kr
  Referer: https://together.daejin.ac.kr
  User-Agent: (공통)
  ```
- **요청 본문/쿼리 파라미터** (form-urlencoded, 쿼리 파라미터 없음):

  | 필드 | 값 | 의미 |
  |---|---|---|
  | targetUrl | `%2FclientMain%2Fa%2Ft%2Fmain.do` (고정) | 로그인 성공 시 이동할 목적지. 페이지는 "추정"이라고 표기. 항상 이 값 그대로 |
  | userId | `{학번}` | URLEncoder.encode(값, "UTF-8") 적용 |
  | userPw | `{비밀번호}` | URLEncoder.encode(값, "UTF-8") 적용 |
- **응답 형식**: 본문은 파싱하지 않음. 인코딩 언급 페이지에 없음.
- **응답 처리(파싱) 규칙**:
  1. 리다이렉트를 모두 따라간 뒤 최종 응답의 상태 코드가 2xx인지 확인
  2. 최종 URL의 path에 문자열 `/login/`이 포함되는지 확인
  3. (1) 참 그리고 (2) 거짓이면 성공, 그 외(2xx 아님 또는 path에 `/login/` 포함)는 실패
  4. 이 API가 돌려주는 데이터는 없음
- **응답 예시**: 페이지에 없음.
- **특이사항/주의**:
  - 포털(www.daejin.ac.kr), 수강신청(dreams2) 로그인과는 완전히 별개의 T-WIN 자체 로그인.
  - HTTP 클라이언트 요건: 리다이렉트 자동 추적, 호스트별 쿠키 저장(같은 이름이 오면 교체, 만료 안 된 것만 전송), 이 저장소를 이후 모든 T-WIN API에서 재사용. 클라이언트를 화면마다 새로 만들면 로그인도 매번 새로 해야 함.
  - 이후 T-WIN API(2, 4, 5, 6, 7, 8, 9번)를 부르기 전 반드시 선행.
  - 헤더 코드블록은 줄바꿈이 사라져 한 줄로 붙어 보이지만 프롬프트에서는 헤더 4개로 구분된다.

### 2. 지도교수 상담 - 상담 인정 현황
- **메서드/주소**: `POST https://together.daejin.ac.kr/myStatus/a/n/getMyStatusListAjax.do`
- **요청 헤더**:
  ```
  Content-Type: application/x-www-form-urlencoded; charset=UTF-8
  IS_AJAX: isAjax
  X-Requested-With: XMLHttpRequest
  Origin: https://together.daejin.ac.kr
  Referer: https://together.daejin.ac.kr/myStatus/a/m/myStatusView.do
  User-Agent: (공통)
  ```
- **요청 본문/쿼리 파라미터** (전부 고정값, 변수 없음, 쿼리 파라미터 없음):

  | 필드 | 값 | 의미 |
  |---|---|---|
  | userId | 빈 문자열 `""` 고정 (`userId=`) | 빈 값 그대로 보냄 |
  | listType | `cns` | 고정 |
  | cnsDiv | `CNSGB01` | 고정 (지도교수 상담 구분 코드) |
- **응답 형식**: HTML 조각 + 안에 박힌 `<script>`. 정리된 표가 아니라 스크립트의 JS 코드를 정규식으로 읽어야 함. 인코딩 언급 페이지에 없음.
- **응답 처리(파싱) 규칙** (응답 전체 대상):
  1. 학기·학년별 횟수: 정규식 `var\s+cnt\s*=\s*parseInt\("(\d+)"\)\s*,\s*grade\s*=\s*parseInt\("(\d+)"\);[\s\S]*?\$\("#term"\+(\d+)\+"_"\+grade\)\.text` 로 전부 찾음. 그룹1=횟수(cnt), 그룹2=학년(grade), 그룹3=학기(term). 매치가 하나도 없으면 전체 실패. 결과는 (학기, 학년) -> 횟수 맵, 그리고 모든 횟수의 합계.
  2. 목표 횟수: 정규식 `var\s+goalCnt\s*=\s*\("([^"]+)"\s*==\s*'B01003'` 의 캡처값이 정확히 `B01003`이면 4, 그 외 값이거나 못 찾으면 12.
  3. 지도교수 staffNo: 정규식 `guidStaffNo=(\d+)` 의 캡처 숫자. 못 찾으면 null (이 경우에도 1, 2는 유효).
  4. 네트워크 실패(타임아웃 등)는 별도 구분.

           phone=010-0000-0000, email=***, guidStaffNm=김교수, guidStaffNo=1234567, shregSt=B01021, ... ]" != "" ){
        setGraduteCnsStatus(); getGraduteCnsProStatusDiv();
  ...
  function setGraduteCnsStatus() {
    var cnt = parseInt("3")
        ,grade = parseInt("1");
    cntByGrade[grade-1] += cnt;
    $("#term"+1+"_"+grade).text(cnt+'회');
    ... (학기/학년 조합마다 반복)

  예시 값: (학기1,학년1)=3, (2,1)=2, (1,2)=2, (2,2)=2, (1,3)=1 -> 합계 10.
- **특이사항/주의**:
  - 선행: 1번 로그인 + 쿠키 재사용.
  - 응답 안에 사용자 개인정보가 담긴 `LoginVO [...]` 문자열이 그대로 들어 있음(학번, 이름, 학과, 학년, 전화, 이메일, 지도교수 이름/직번, 학적상태 등). 페이지는 이 중 `guidStaffNo`만 정규식으로 사용한다.
  - 목표 횟수 판정의 `B01003`은 페이지 스크립트 주석상 "편입학"(목표 4회), 일반 학생은 12회. 예시의 `shregSt`는 `B01021`(일반복학)이라 12가 된다. (`B01021`/`B01003`와 학적상태명의 대응은 `LoginVO`와 스크립트 주석에서 읽은 것이며, 별도 명세 문장은 아님.)

  - 4학년 2학기일 때만 충족/미충족 표시(그 전은 `-`)는 화면 스크립트 로직이며, 파싱 규칙에는 포함되지 않음.

### 3. 지도교수 상담 - 내 지도교수 이름 조회 (dreams2)
- **메서드/주소**: `GET https://dreams2.daejin.ac.kr/sugang/center/Bshr020101.jsp`
- **요청 헤더**:
  ```
  Cookie: userId={userId2}; orgCd=ZjzT1v9Ax6ybAbmfZIWOsA%3D%3D;
  User-Agent: (공통)
  ```
- **요청 본문/쿼리 파라미터**: 본문 없음, 쿼리 없음.
  - Cookie `userId`: 로그인에서 얻은 userId2(SSO uid) 값
  - Cookie `orgCd`: 고정 상수 `ZjzT1v9Ax6ybAbmfZIWOsA%3D%3D` (앱 전역에서 재사용)
- **응답 형식**: HTML. **EUC-KR 인코딩** (UTF-8로 읽으면 한글이 깨짐, 예시 meta도 `charset=euc-kr`).
- **응답 처리(파싱) 규칙**:
  1. 셀렉터 `td.tr_chrm1_n` 요소를 전부 찾음
  2. 그중 텍스트가 정확히 `지도교수`인 요소를 찾음, 없으면 실패
  3. 그 요소의 바로 다음 형제(nextElementSibling)를 가져옴, 없으면 실패
  4. 형제 텍스트(앞뒤 공백 제거)가 비어 있지 않으면 그것이 지도교수 성함, 비어 있으면 실패
  5. 네트워크 실패는 별도 구분
- **최종 산출물**: 지도교수 성함(문자열) 또는 실패.
- **응답 예시** (발췌):
  ```html
  <td align="center" width="14%" class="tr_chrm1_n">학번</td>
  <td align="center" width="19%" class="tr_a_n">20230000</td>
  <td align="center" width="14%" class="tr_chrm1_n">이름</td>
  <td align="center" width="19%" class="tr_a_n">홍길동</td>
  ...
  <td class="tr_chrm1_n">지도교수</td>
  <td class="tr_a_n">김교수</td>
  <td class="tr_chrm1_n">대학</td> <td class="tr_a_n">OO대학</td>
  <td class="tr_chrm1_n">학과</td> <td class="tr_a_n">OO전공</td>
  ```
- **특이사항/주의**:
  - 이 API만 T-WIN이 아닌 dreams2(수강신청 시스템) 호스트이며, T-WIN 로그인 쿠키가 아니라 `userId`+`orgCd` 쿠키 쌍으로 인증. 별도 세션 유지/리다이렉트 처리 불필요.
  - 선행 조건은 "userId2(SSO uid)를 가지고 있어야 함"이라고만 적혀 있고, userId2를 얻는 방법은 페이지에 없음.
  - 같은 페이지에 학적 정보(학번/이름/입학/학과/변동 내역 등)가 있지만 파싱 규칙은 지도교수 성함만 해당.
  - 셀렉터는 `td.tr_chrm1_n`(라벨 셀 클래스)인 반면 값 셀 클래스는 `tr_a_n`. 규칙은 "라벨 다음 형제"로 되어 있어 일치함.

### 4. 지도교수 상담 - 상세보기 (상담 이력 상세)
- **메서드/주소**: `POST https://together.daejin.ac.kr/cnsHis/a/n/getCnsDetailInfoPop.do`
- **요청 헤더**:
  ```
  Content-Type: application/x-www-form-urlencoded; charset=UTF-8
  IS_AJAX: isAjax
  X-Requested-With: XMLHttpRequest
  Origin: https://together.daejin.ac.kr
  Referer: https://together.daejin.ac.kr/myCns/a/m/getMyCnsMain.do
  User-Agent: (공통)
  ```
- **요청 본문/쿼리 파라미터** (쿼리 없음):

  | 필드 | 값 | 의미 |
  |---|---|---|
  | cnsKeyId | `{상담 이력 고유 키}` | 5번(이력 목록) 응답에서 얻은 키. 호출자가 전달 |
  | cnsOnoffDiv | `ON` 고정 | 온라인/방문 여부와 무관하게 항상 `ON` (코드상 분기 없음) |
  | cnsDiv | `CNSGB01` 고정 | |
- **응답 형식**: HTML (팝업 조각). 인코딩 언급 페이지에 없음.
- **응답 처리(파싱) 규칙**:
  1. `table tbody tr` 각 행에서 `th`를 라벨, `td`를 값으로 하는 라벨->값 맵 생성

  3. `답변일시`/`답변 내용`이 둘 다 없으면 교수가 아직 답변 안 한 정상 상황(에러 아님)
  4. 첨부파일 관련 행(나의 첨부파일, 회신 첨부파일)이 있어도 조회하지 않고 무시
  5. 네트워크 실패는 별도 구분
- **최종 산출물**: {신청일시, 상태, 신청내용, 답변일시|null, 답변내용|null}.
- **응답 예시** (발췌):
  ```html
  <tbody>
    <tr><th scope="row">신청일시</th><td>2026-06-01</td></tr>
    <tr><th scope="row">답변일시</th><td>2026-06-10</td></tr>
    <tr><th scope="row">상태</th><td class="font_nightblue bold">상담 완료</td></tr>
    <tr><th scope="row">신청 내용</th><td>교수님 사랑합니다!</td></tr>
    <tr><th scope="row">나의 첨부파일</th><td> ...form/file input... </td></tr>
    <tr><th scope="row">회신 첨부파일</th><td></td></tr>
    <tr><th scope="row">답변 내용</th><td class="preline"><p>확인완료</p></td></tr>
  ```
- **특이사항/주의**:
  - 선행: 1번 로그인 + 5번에서 cnsKeyId 확보.
  - 예시에서 `답변일시`는 `신청일시` 바로 뒤, `상태`보다 앞에 있음(행 순서는 맵 방식이므로 영향 없음).
  - 답변 내용 셀은 `<p>`를 포함한 HTML 조각일 수 있음(예시). 텍스트 추출 방식은 페이지에 명시 없음.
  - 응답 스크립트에 첨부 업로드(`.../cnsHis/w/n/createOnCnsStdFileAttach.do`) 로직이 보이지만 명세 대상 아님.

### 5. 지도교수 상담 - 상담 신청 이력 (목록, 페이지네이션)
- **메서드/주소**: `POST https://together.daejin.ac.kr/cnsHis/a/n/getCnsHisListAjax.do`
- **요청 헤더**:
  ```
  Content-Type: application/x-www-form-urlencoded; charset=UTF-8
  IS_AJAX: isAjax
  X-Requested-With: XMLHttpRequest
  Origin: https://together.daejin.ac.kr
  Referer: https://together.daejin.ac.kr/myCns/a/m/getMyCnsMain.do
  User-Agent: (공통)
  ```
- **요청 본문/쿼리 파라미터** (쿼리 없음):

  | 필드 | 값 | 의미 |
  |---|---|---|
  | pageIndex | `{페이지 번호, 1부터}` | 페이지당 5건 고정(실제 호출로 확인됐다고 기재) |
  | cnsDiv | `CNSGB01` | 고정 |
  | regId | `{학번}` | 학번 문자열 그대로 |
- **응답 형식**: HTML. 인코딩 언급 페이지에 없음.
- **호출 순서(페이지네이션)**:
  1. `pageIndex=1`로 먼저 호출
  2. 첫 응답 HTML에서 정규식 `var\s+totalCnt\s*=\s*'(\d+)'` 로 전체 건수 추출, 못 찾으면 0
  3. 전체 페이지 수 = ceil(전체 건수 / 5). 0건이면 페이지 수 1로 보고 더 호출 안 함
  4. 페이지 수가 1보다 크면 `pageIndex=2`부터 끝까지 나머지를 동시에(병렬) 호출
  5. 1페이지 항목 + 나머지 페이지 항목을 순서대로 이어붙인 것이 최종 결과
- **응답 처리(파싱) 규칙** (페이지 하나당):
  1. `table tbody tr` 각 행에서 `td` 셀을 가져옴. 셀이 5개 미만이면 행 건너뜀
  2. 5번째 셀(인덱스 4) 안 `button`의 `data-param1` 속성값 = cnsKeyId. 비어 있으면 행 건너뜀

  - 상담내용 길이 제한, 전화번호/이메일 형식 검증 등은 페이지에 없음.
  - 방문 신청은 쓰기 동작이라 URL 경로가 `/w/`(write)임(다른 조회는 `/r/` 또는 `/a/`가 아닌 `a/n`). 이 해석은 추정.
