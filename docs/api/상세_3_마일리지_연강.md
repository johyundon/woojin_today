### 1. 마일리지 - 로그인 (T-WIN 로그인)
- **메서드/주소**: `POST https://together.daejin.ac.kr/login/a/n/loginProc.do`
- **요청 헤더**:
```txt
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Origin: https://together.daejin.ac.kr
Referer: https://together.daejin.ac.kr
User-Agent: (공통 UA)
```
- **요청 본문** (쿼리 파라미터 없음):

| 필드 | 값 | 의미 |
|---|---|---|
| targetUrl | `%2FclientMain%2Fa%2Ft%2Fmain.do` (고정) | 로그인 성공 후 이동 목적지. 디코딩하면 `/clientMain/a/t/main.do`. 목적지 파라미터라는 설명은 "(추정)"이라고 페이지에 적혀 있음 |
| userId | `{학번}` | `URLEncoder.encode(값, "UTF-8")` 적용 |
| userPw | `{비밀번호}` | 동일하게 URL 인코딩 |

- **응답 형식**: 페이지에 응답 예시 없음. "응답 바디는 파싱하지 않는다"고 명시. 인코딩 언급 없음.
- **응답 처리(파싱) 규칙**:
  1. 리다이렉트를 모두 따라간 뒤 최종 응답의 상태 코드가 2xx인지 확인.
  2. 최종 URL의 경로(path)에 문자열 `/login/`이 포함되어 있는지 확인.
  3. (1) 참 + (2) 거짓이면 로그인 성공.
  4. 그 외(2xx 아님, 또는 최종 경로에 `/login/` 포함)면 로그인 실패.
  - 이 API가 돌려주는 데이터는 없음. 위 판정이 전부.
- **응답 예시**: 페이지에 없음.
- **특이사항/주의**:
  - 포털(www.daejin.ac.kr), 수강신청(dreams2.daejin.ac.kr) 로그인과 완전히 별개인 T-WIN 자체 로그인.
  - 이후 T-WIN API(랭킹/마일리지현황/지도교수상담 등) 호출 전에 반드시 먼저 성공해야 함.
  - HTTP 클라이언트 요건: 리다이렉트 자동 추적. 호스트별 쿠키 저장소 필요(같은 이름 쿠키가 오면 교체, 만료 안 된 쿠키만 전송). 이 쿠키 저장소를 이후 T-WIN 모든 호출에서 재사용. Cookie 헤더를 직접 세팅하지 않고 저장소에 맡김.
  - 화면마다 클라이언트를 새로 만들면 로그인도 매번 다시 해야 함. 공유하려면 클라이언트 인스턴스를 앱 레벨에서 공유.
  - 페이지 내 표기 차이: Header 코드블록은 줄바꿈이 깨져 `Content-Type...UTF-8Origin:...` 처럼 붙어 보임. 프롬프트 [2]도 같은 이유로 붙어 있음. 헤더는 3개(+UA)로 해석됨.

### 2. 마일리지 - 내 현황 조회
- **메서드/주소**: `POST https://together.daejin.ac.kr/myStatus/a/n/getMyStatusListAjax.do`
- **요청 헤더**:
```txt
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
is_ajax: isAjax          (프롬프트에는 IS_AJAX: isAjax 로 표기)
X-Requested-With: XMLHttpRequest
Origin: https://together.daejin.ac.kr
Referer: https://together.daejin.ac.kr/myStatus/a/m/myStatusView.do
User-Agent: (공통 UA)
```
- **요청 본문**: `listType=mileage` (고정값 하나뿐, 변수 없음). 쿼리 파라미터 없음.
- **응답 형식**: HTML. 인코딩 언급 없음.
- **응답 처리(파싱) 규칙**:
  1. `div.mymileage_score p strong` 텍스트를 정수로 변환 = 내 마일리지 점수.
  2. `div.ranking` 요소의 직접 텍스트(자식 태그 제외)에서 정규식 `\d+`로 찾은 숫자 = 내 순위.
  3. 1)과 2) 중 하나라도 못 찾으면 실패.
  4. 전체 순위 TOP5: 문서의 모든 `tr`을 훑어, `th` 텍스트가 정규식 `^(\d+)위$`에 매치되는 행만 골라 그 행의 첫 번째 `td` 텍스트를 정수로 변환. (순위, 점수) 쌍을 순위 오름차순 정렬해 점수만 나열한 것이 top5.
  5. 네트워크 실패(타임아웃 등)는 별도 구분 처리.
  - 최종 산출물: 내 점수(정수), 내 순위(정수), top5 점수 목록(1위부터).
- **응답 예시** (발췌):
```html
<div class="mymileage_score">
  <p>나의 마일리지 <strong>0</strong></p>
  <div class="ranking">46 위 <strong class="mileage_tit">나의 마일리지 순위</strong></div>
  <strong class="mileage_info">※ 동일학년 기준</strong>
</div>
...
<tbody>
  <tr><th scope="row">1위</th><td>80</td></tr>
  <tr><th scope="row">2위</th><td>72</td></tr> ... (5위까지)
</tbody>
```
- **특이사항/주의**:
  - 선행 조건: T-WIN 로그인 성공 + 같은 쿠키 저장소 재사용. 리다이렉트 여부로 판단하지 않음.
  - 예시의 TOP5 표(`1위 80, 2위 72, 3위 64, 4위 32, 5위 26`)는 "동일학년 기준" 표다. 같은 응답 아래쪽에 "구분별 등수" 표(`th`가 `구분/학교전체/단과대학/학과`, 순위는 `td`에 `1위…5위`)도 있으나, 이 표의 `th`는 `^(\d+)위$`에 매치되지 않아 파싱 대상이 아님.
  - 예시의 `div.ranking` 텍스트가 `46` / `위`로 줄바꿈되어 있어 `\d+`로 46을 얻는 구조. 또 "나는 현재 '학교전체' 기준 132위 / 단과대학 6위 / 동일학과 3위" 문구가 있으나 파싱 규칙에는 쓰이지 않음. 이 값(46 vs 132)이 서로 다른 기준임은 페이지 설명에 없음 (추정: 46은 동일학년 기준 순위).
  - 응답 HTML 하단 스크립트에 후속 호출이 박혀 있음(규칙에 포함되지 않은 정보): `getMileageStatusInfoAjax.do`(지급내역, 파라미터 userId/sustCd/shyrCd/pageIndex), `getCertiListAjax.do`(파라미터 stdNo/sustCd/shyrCd). 지급내역 API의 sustCd/shyrCd 값은 이 스크립트(응답의 LoginVO)에서 얻는 구조로 보임(추정, 페이지는 "호출하는 쪽이 넘겨야 하는 값"이라고만 설명).
  - 응답 예시 `<script>` 안에 LoginVO 전체 덤프(이름, 학번, 전화, 이메일, 지도교수, 학과코드 등 개인정보 다수)가 그대로 노출됨. 본 문서에는 옮기지 않음. 포함 필드명 예: `userId, userName, shyrCd, colgCd, sustCd, sustCdNm, guidStaffNm, guidStaffNo, shregSt, phone, email, credit`. 값 형태 예: `sustCd=AA0194`(학과코드), `shyrCd=3`(학년코드).
  - 헤더 표기 불일치: Header 블록은 `is_ajax`, 프롬프트는 `IS_AJAX` (HTTP 헤더는 대소문자 구분 안 하므로 동일 취급 가능, 이는 추정).
  - 응답 예시의 `<table>` 안에 `<table>`이 중첩되어 있음(원문 HTML이 그러함).

### 3. 마일리지 - 공지글 조회 (마일리지 장학 공지 목록)
- **메서드/주소**: `GET https://www.daejin.ac.kr/daejin/1002/subview.do?enc={조립된 값}`
- **요청 헤더**: `User-Agent: (공통 UA)` 만. 바디 없음.
- **쿼리 파라미터** (`enc`):
  - 페이지 Parameter 블록의 예시 값(개행으로 끊겨 있음): `enc=Zm5jdDF8QEB8JTJGYmJzJTJGZGFlamluJTJGMTg5JTJGYXJ0Y2xMaXN0LmRvJTNGYmJzQ2xTZXElM0QlMjZiYnNPcGVuV3JkU2VxJTNEJTI2aXNWaWV3TWluZSUzRGZhbHNlJTI2c3JjaENvbHVtbiUzRHNqJTI2c3JjaFdyZCUzRCVFQiVBNyU4OCVFQyU5RCVCQyVFQiVBNiVBQyVFQyVBNyU4MCVFQyU5RSVBNSVFRCU5NSU5OSUyNg==`
  - 조립 규칙:
    1. 문자열 = `"/bbs/daejin/189/artclList.do?bbsClSeq=&bbsOpenWrdSeq=&isViewMine=false&srchColumn=sj&srchWrd="` + URL인코딩("마일리지장학") + `"&"`
    2. 이 전체 문자열을 URL 인코딩.
    3. `"fnct1|@@|"` 뒤에 2)의 결과를 붙임.
    4. 3)의 결과 전체를 base64 인코딩 = enc 값.
  - 게시판 번호(189)와 검색어("마일리지장학")는 고정값이라 매번 같은 enc가 나옴.
- **응답 형식**: HTML (`<meta charset="UTF-8">`가 예시 head에 있음).
- **응답 처리(파싱) 규칙**:
  1. `table.board-table tbody tr` 행 선택.
  2. 각 행: `td.td-subject` 안의 `a`가 없으면 건너뜀.
  3. 제목: `a` 안에 `strong`이 있으면 그 텍스트, 없으면 `a`의 직접 텍스트. 앞뒤 공백 제거.
  4. 제목이 비었거나 "마일리지"가 포함되지 않으면 행을 버림 (서버 검색어 "마일리지장학"보다 느슨한 클라이언트 쪽 2차 필터).
  5. 작성자 = `td.td-write` 텍스트.
  6. 날짜 = `td.td-date` 텍스트.
  7. 조회수 = `td.td-access` 텍스트.
  8. 첨부 여부 = 행 안에 `td.td-file p.file-y`가 있으면 true.
  9. 신규글 여부 = `a` 안에 `span.new`가 있으면 true.
  10. 상세경로 = `a`의 href 그대로 (도메인 없는 상대경로, 열려면 `https://www.daejin.ac.kr` + 값).
  11. 페이지네이션 없음. 이 응답 하나가 전부.
  12. 네트워크 실패는 별도 구분 처리.
  - 최종 산출물: `[{제목, 작성자, 날짜, 조회수, 첨부여부, 신규여부, 상세경로}]`

```html

  <tr class="notice ">
```

- **특이사항/주의**:
  - 로그인 불필요하나, www.daejin.ac.kr 내부 SSO 확인 절차(`checkToken.do` -> `nsso` -> 원래 주소 복귀 리다이렉트 체인)를 타야 함. 페이지는 "코드 주석에 따르면 체인 없이 artclList.do를 바로 호출하면 srchWrd가 무시되고 상단 고정글만 내려온다"고 설명. 호스트별 쿠키 저장/재사용 쿠키 저장소 필요(학사공지 목록 조회 API와 동일 이유라고 적혀 있으나 그 API는 이 7개 페이지에 없음).
  - 예시 응답에서 `td.td-access`는 일치하지만 `th`는 `th-acess`(오타 형태)임. 파싱은 `td-access`를 쓰므로 영향 없음.
  - 예시 HTML에는 `span.new`가 한 번도 등장하지 않음(0건). 신규글 판정 규칙은 예시로 검증되지 않음. 첨부 표시는 `p.file-n`(0건) / `p.file-y`가 확인됨.
  - 예시의 상단 `tr.notice`(일반공지) 행들은 마일리지와 무관한 제목이 섞여 있어(예: 추가 등록 안내) 위 4번 필터가 실제로 필요함을 보여줌 (예시 내용 기준 추정).
  - 페이지의 응답 예시는 매우 큼(전체 HTML, 약 21만자). 위는 핵심만 발췌.

### 4. 마일리지 - 지급내역
- **메서드/주소**: `POST https://together.daejin.ac.kr/myStatus/a/n/getMileageStatusInfoAjax.do`
- **요청 헤더**:
```txt
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
IS_AJAX: isAjax
X-Requested-With: XMLHttpRequest
Origin: https://together.daejin.ac.kr
Referer: https://together.daejin.ac.kr/myStatus/a/m/myStatusView.do
User-Agent: (공통 UA)
```
- **요청 본문** (쿼리 파라미터 없음):

| 필드 | 예시 | 의미 |
|---|---|---|
| userId | `{학번}` | 학번 그 자체. 로그인 시 별도 발급되는 SSO uid가 아님 |
| sustCd | `{학과코드}` | 예: `AA0194` (2번 페이지 응답 스크립트의 값 형태) |
| shyrCd | `{학년코드}` | 예: `3` |
| pageIndex | `{페이지 번호}` | 1부터 시작하는 정수. 페이지당 5건 |

- **응답 형식**: HTML. 인코딩 언급 없음.
- **호출 순서(페이지네이션)**:
  1. `pageIndex=1`로 먼저 호출.
  2. 첫 응답 HTML 안 JS 변수에서 정규식 `var\s+totalCnt\s*=\s*'(\d+)'`로 전체 건수 추출. 못 찾으면 0.
  3. 전체 페이지 수 = ceil(전체 건수 / 5). 건수가 0이면 페이지 수 1로 취급하고 추가 호출 안 함.
  4. 페이지 수 > 1이면 `pageIndex=2 ~ 페이지수`를 동시에(병렬) 호출.
  5. 페이지1, 2, 3... 순서대로 이어붙인 것이 최종 결과.
- **응답 처리(파싱) 규칙** (페이지 하나당):
  1. `table tbody tr` 각 행에서 `th`와 `td`를 구분 없이 나오는 순서대로 합쳐 셀 목록 생성.
  2. 셀이 4개 미만이면 행 건너뜀.
  3. 0번째 = 날짜, 1번째 = 구분(카테고리), 2번째 = 활동명, 3번째를 정수로 변환 = 점수 (변환 실패 시 0).
  4. 네트워크 실패는 별도 구분 처리.
  - 최종 산출물: `[{날짜, 구분, 활동명, 점수}]` (전체 페이지 순서대로).
- **응답 예시** (발췌, 페이지에 실린 샘플 값 그대로):
```html
<thead><tr><th>획득일</th><th>구분</th><th>활동명</th><th>획득 마일리지</th></tr></thead>
<tbody>
  <tr><td>2026-03-15</td><td>봉사활동</td><td>교내 도서관 봉사</td><td>5</td></tr>
  <tr><td>2026-04-02</td><td>학술활동</td><td>학과 세미나 참석</td><td>3</td></tr>
</tbody>
...
<script> var currentPage = '1'; var totalCnt = '0'; ... </script>
```
- **특이사항/주의**:
  - 선행 조건: T-WIN 로그인 성공 + 쿠키 저장소 재사용.
  - 페이지 크기 5는 API가 알려주는 값이 아니라 호출해서 확인된 고정 크기. HTML 안에서도 `fnCreatePageingView_std(totalCnt, 5, 5, ...)`로 5가 보임.
  - 예시 응답은 `totalCnt = '0'`인데 `tbody`에는 2행이 있음 (모순). 예시가 실제 응답이 아니라 손으로 만든 샘플일 가능성이 있음(추정). 이 예시대로면 규칙상 전체 건수 0 -> 1페이지만 처리.
  - 예시의 `thead` 행(`th` 4개)은 `tbody`가 아니라서 `table tbody tr` 선택자에 걸리지 않음.
  - 파싱 규칙에는 th/td 혼합이라고 되어 있지만 예시는 td 4개만 사용.

### 5. 마일리지 - 상세조회 (공지 상세페이지 xlsx 첨부 확인)
- **메서드/주소**: `GET https://www.daejin.ac.kr{detailPath}` 예: `https://www.daejin.ac.kr/bbs/daejin/189/461951/artclView.do`
- **요청 헤더**: `User-Agent: (공통 UA)` 만.
- **요청 본문/쿼리 파라미터**: 없음. `detailPath`는 URL 경로에 포함됨 (3번 API의 상세경로 값을 그대로 이어붙임).
- **응답 형식**: HTML. 인코딩 언급 없음.
- **응답 처리(파싱) 규칙**:
  1. `a.file-download` 요소를 찾음. 없으면 첨부 없음으로 확정.
  2. 요소 텍스트(파일명)가 `.xlsx`로 끝나는지 확인(대소문자 무시). 아니면 첨부 없음으로 확정.
  3. `.xlsx`로 끝나면 요소의 href(도메인 없는 상대경로)를 가져와 `https://www.daejin.ac.kr` + href = 최종 다운로드 URL.
  4. 네트워크 실패는 별도 구분 처리.
  - 최종 산출물: 다운로드 URL 문자열 또는 null (첨부 없음/xlsx 아님).
- **응답 예시**: 페이지에 없음.
- **특이사항/주의**:
  - 로그인 불필요, 쿠키 저장소도 반드시 필요하지는 않음.
  - `a.file-download` 중 첫 번째 요소만 다루는지, 여러 개일 때 처리는 페이지에 없음 ("요소"라고만 표현).
  - 프롬프트에서 입력 이름이 `detailPath`로 되어 있고, Parameter 블록 표현도 동일해 일관됨.

### 6. 마일리지 - 대상자 확인 (명단 xlsx 다운로드 및 학번 대조)
- **메서드/주소**: `GET https://www.daejin.ac.kr{downloadUrl}` 예: `https://www.daejin.ac.kr/bbs/daejin/189/331328/download.do`
- **요청 헤더**: `User-Agent: (공통 UA)` 만. 바디 없음.
- **파라미터**: 없음 (`downloadUrl`이 URL 경로에 포함).
- **응답 형식**: 바이너리 xlsx (zip). 텍스트로 읽으면 깨지므로 바이트 배열로 받아야 함. 2xx가 아니면 즉시 에러.
- **응답 처리(파싱) 규칙** (Apache POI 없이 zip+XML만 이용):
  1. zip에서 `xl/sharedStrings.xml`과 `xl/worksheets/sheet숫자.xml` 패턴 파일들을 모두 수집(시트 여러 개 가능).
  2. `sharedStrings.xml` 파싱: 각 `<si>...</si>` 블록마다 안의 모든 `<t>...</t>` 조각을 순서대로 이어붙여 한 문자열로 만들고, XML 엔티티(`&lt; &gt; &quot; &apos; &amp;`)를 원래 문자로 복원. 순서대로 배열에 담아 "공유 문자열 테이블" 구성.
  3. 각 시트 XML에서 `<c 속성들>...<v>값</v>...</c>` 셀 블록을 모두 찾음:
     - `<v>`가 없거나 비어 있으면 그 셀 무시.
     - 셀 속성에 `t="s"`가 있으면 `<v>`는 공유 문자열 인덱스. 테이블에서 실제 문자열을 찾음(인덱스 범위 밖이면 원래 값을 그대로 문자열로 사용).
     - `t="s"`가 없으면 `<v>` 값을 그대로 문자열로 사용.
  4. 모든 시트의 모든 셀 값을 하나의 문자열 목록으로 합침 ("명단 파일 전체 셀 값").
  5. 목록에 확인하려는 학번 문자열과 정확히 일치하는 값이 있으면 "대상자임". 없으면 "대상자 아님" (이때 전체 셀 값 목록도 같이 반환해 화면에서 검색 가능한 명단으로 보여줌).
  6. 네트워크 실패(타임아웃, 응답 실패 등)는 별도 구분 처리.
  - 최종 산출물: "대상자임" / "대상자 아님(전체 셀 값 목록 포함)" / "다운로드 실패".
- **응답 예시**: 페이지에 없음.
- **특이사항/주의**:
  - 로그인 불필요.
  - 프롬프트는 `{downloadUrl}`을 "상세페이지 확인 API(5번)의 응답에서 얻은 완전한 URL을 그대로 쓴다"고 설명하지만, 제목/주소 표기는 `https://www.daejin.ac.kr{downloadUrl}`이라 도메인이 중복될 수 있는 모순이 있음. 5번은 이미 `https://www.daejin.ac.kr`을 붙인 완전한 URL을 반환하므로, 6번에서는 도메인을 다시 붙이지 말아야 함(해석, 추정).
  - 일치 비교는 "정확히 일치"이며 학번이 숫자 셀(`t="s"` 없음)일 때는 `<v>` 값 문자열 그대로 비교된다는 뜻으로 읽힘.
  - 예시의 `331328.download.do`와 5번의 `461951.artclView.do` 글 번호가 서로 다름(예시일 뿐, 서로 연결된 값이 아님).

### 7. 연강이 가능할까요? (카카오맵)
- **상태**: 페이지는 열렸으나 **API 명세 내용이 없음**. Header/Body/Parameter/프롬프트/응답 예시 모두 없음.
- **페이지에 있는 것**: 첨부 파일 블록 2개뿐.
  - `campus_paths.geojson` (캠퍼스 길 데이터로 보이는 파일, 내용은 읽지 않음: 첨부 다운로드 필요)
  - `CampusBuildingCatalog.kt` (캠퍼스 건물 목록 코틀린 파일로 보임, 내용은 읽지 않음)
  - 둘 다 `notion-file-block://` 참조로만 표시됨. 파일 내용은 이번 작업에서 가져오지 않았음.
- **메서드/주소, 요청 헤더, 파라미터, 응답 형식, 파싱 규칙, 응답 예시**: 페이지에 없음.
- **특이사항**: 제목(카카오맵, 연강 가능 여부)으로 볼 때 건물 간 이동 시간 계산 관련 자료일 가능성이 있으나(추정), 페이지에는 설명이 전혀 없음. 필요하면 첨부 2개를 `notion-get-file-download-urls` 등으로 받아 별도로 읽어야 함.
