# API 명세 정리 (Part A: 노션 페이지 8개)

출처: 노션 "Flutter 기록 / Request/Response (1)" 데이터베이스의 페이지 8개 (모두 정상 조회됨).
공통 사항(페이지에 적힌 것):
- User-Agent는 대부분 `Mozilla/5.0 (Linux; Android 14; Mobile) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128.0.0.0 Mobile Safari/537.36` 로 고정 (날씨 API만 예외).
- dreams2 계열 API(3~6번)의 Cookie 블록에는 "고정 상수" 쿠키가 들어간다. 값은 노션 원문에 그대로 있으나 개인 식별 가능성이 있어 이 문서에서는 `***`로 가린다. 필요하면 각 노션 페이지의 Header 블록을 직접 볼 것.
- "네트워크 자체가 실패한 경우(타임아웃 등)는 별도로 구분해서 처리한다"는 문장이 학번 찾기~이수구분표(2) 모든 페이지에 공통으로 있다.
- 노션 속성: 모든 페이지가 `API 분류=API Response`, `태그=DTO(요청 객체)`.

### 1. 날씨 (대진대 날씨 조회, Open-Meteo)
- 노션: https://app.notion.com/3563c48d630d83c995fd01a0944c5872
- **메서드/주소**: `GET https://api.open-meteo.com/v1/forecast` (학교 서버와 무관한 외부 무료 API, 키/가입 불필요)
- **요청 헤더**: 없음 (커스텀 헤더 없음, HTTP 클라이언트 기본 헤더만. User-Agent도 별도로 안 붙임)
- **요청 본문/쿼리 파라미터**: Body 없음. 매 호출 완전히 동일한 URL.

| 파라미터 | 값 | 의미 |
|---|---|---|
| latitude | 37.8708627 | 대진대 캠퍼스 중심 좌표 고정 (GPS 사용 안 함) |
| longitude | 127.1568845 | 위와 동일 |
| current | temperature_2m,relative_humidity_2m,apparent_temperature,precipitation,weather_code,wind_speed_10m | 현재 관측값 필드 |
| hourly | temperature_2m,precipitation,precipitation_probability,weather_code | 1시간 단위 예보 필드 |
| daily | temperature_2m_max,temperature_2m_min,precipitation_sum,precipitation_probability_max,weather_code | 일별 예보 필드 |
| timezone | Asia/Seoul | 응답 시각 기준 시간대 |
| forecast_days | 7 | 오늘 포함 7일 |

- **응답 형식**: JSON 하나. 인코딩 언급 페이지에 없음.
- **응답 처리(파싱) 규칙**:
  - 알 수 없는 필드는 무시하도록 설정.
  - 최상위: `current`(객체), `hourly`(객체), `daily`(객체).
  - `current`에서 3개만 사용: `temperature_2m`(숫자, 현재 기온), `weather_code`(정수), `precipitation`(숫자, 현재 강수량). `relative_humidity_2m`, `apparent_temperature`, `wind_speed_10m`는 응답에 있어도 버림.
  - `hourly`에서 3개만 사용: `time`(문자열 배열), `temperature_2m`(배열), `weather_code`(배열). 세 배열은 같은 순서/길이. `precipitation`, `precipitation_probability`는 버림.
  - `daily` 5개 전부 사용: `time`, `temperature_2m_max`, `temperature_2m_min`, `precipitation_sum`, `precipitation_probability_max`, `weather_code` (각각 배열; 필드 수로는 time 포함 6개).
  - HTTP 실패 또는 바디가 비어 있으면 에러.
  - 최종 산출물: `{currentTemp, currentWeatherCode, currentPrecipitation, hourly:[{time,temperature,weatherCode}], daily:[{date,tempMax,tempMin,precipitationSum,precipitationProbabilityMax,weatherCode}]}`
- **응답 예시(발췌)**:
```json
{"latitude":37.85,"longitude":127.1875,"timezone":"Asia/Seoul","utc_offset_seconds":32400,
 "current":{"time":"2026-09-04T12:15","interval":900,"temperature_2m":26.4,"relative_humidity_2m":62,"apparent_temperature":28.5,"precipitation":0.00,"weather_code":0,"wind_speed_10m":17.9},
 "hourly":{"time":["2026-09-04T00:00","2026-09-04T01:00",...],"temperature_2m":[20.9,20.5,...],"precipitation":[...],"precipitation_probability":[...],"weather_code":[1,0,...]},
 "daily":{"time":["2026-09-04",...7개],"temperature_2m_max":[27.1,...],"temperature_2m_min":[17.7,...],"precipitation_sum":[0.00,...],"precipitation_probability_max":[0,0,4,2,2,14,7],"weather_code":[1,1,3,3,1,3,3]}}
```
  단위: current/hourly 기온 °C, 강수 mm, 풍속 km/h, 날씨코드는 "wmo code", 시각은 iso8601(분 단위, 초 없음).
- **특이사항/주의**:
  - 응답의 latitude/longitude는 37.85/127.1875로, 요청 좌표(37.8708627/127.1568845)와 다르다(서버가 격자 중심으로 보정한 값으로 추정).
  - hourly는 7일 x 24시간 = 168개 항목.
  - 로그인/쿠키/리다이렉트 처리 불필요.
  - 페이지 Parameter 블록은 줄바꿈이 사라져 `...37.8708627longitude=127.1568845current=...`처럼 `&`가 빠져 보이나, 프롬프트의 URL에는 `&`가 정상 표기됨.

### 2. 학번 찾기
- 노션: https://app.notion.com/f2e3c48d630d82a4961e017327cc5af3
- **메서드/주소**: `POST https://www.daejin.ac.kr/userInfoSearch/daejin/1/idSearch.do`
- **요청 헤더**:
```
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
User-Agent: Mozilla/5.0 (Linux; Android 14; Mobile) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128.0.0.0 Mobile Safari/537.36
```
- **요청 본문**(쿼리 파라미터 없음):

| 필드 | 값 | 의미 |
|---|---|---|
| findType | 2 | 고정 |
| srchGubun | 1 | 고정 |
| srchNm | {이름} | `URLEncoder.encode(값,"UTF-8")` 적용 |
| srchBirthday | 예: 990101 | YY+MM+DD를 구분자 없이 문자열로 이어붙인 6자리. 별도 인코딩 없음 |
| srchMobile1 | 010 등 | 휴대폰 앞자리, 인코딩 없음 |
| srchMobile2 | 중간자리 | 인코딩 없음 |
| srchMobile3 | 뒷자리 | 인코딩 없음 |

- **응답 형식**: HTML 한 장(리다이렉트 체인 없음, 단일 응답). 인코딩 페이지에 없음.
- **응답 처리(파싱) 규칙**:
  - 정규식 `조회된\s*학번은\s*<strong>\s*(\d+)\s*</strong>` 매치 여부만 확인.
  - 매치되면 성공, 캡처 그룹 1(숫자)이 학번.
  - 매치 안 되면 곧바로 NotFound (실패 사유 텍스트 파싱 불필요).
  - 네트워크 실패는 NetworkError로 별도 구분.
  - 산출물: `studentNo: String?` (찾으면 학번, 못 찾으면 null, 네트워크 실패는 별도 에러).
- **응답 예시**: 페이지에 없음 (성공 HTML 예시 미첨부).
- **특이사항/주의**: 로그인/세션/쿠키 저장소 불필요한 공개 API. 요청 예시는 있으나 응답 예시가 없어 정규식 대상 HTML은 확인 불가.

### 3. 시간표 - 개설과목 조회 (개설과목 카탈로그)
- 노션: https://app.notion.com/0303c48d630d8372831c016f0b7c4ba5
- **메서드/주소**: `GET https://dreams2.daejin.ac.kr/sugang/center/ProLsnAply06.jsp?fhd_yyyy={연도}&fhd_shtm={학기}&ic_kwa={...}(&ic_kwa_1={학과코드})`
- **요청 헤더**:
```
Cookie: JSESSIONID={jsessionId}; user_id=***; userId=***; nm=***; userFlag=***; userMjCd=***; resd1=***; resd2=***; orgCd=***; seq=***; wkkdCd=***; passwd=***; cookWebUser=***; WMONID={wmonid}
User-Agent: Mozilla/5.0 (Linux; Android 14; Mobile) ... Chrome/128.0.0.0 Mobile Safari/537.36
```
  - JSESSIONID, WMONID: 로그인 시 얻은 값. 나머지 12개(user_id/userId/nm/userFlag/userMjCd/resd1/resd2/orgCd/seq/wkkdCd/passwd/cookWebUser)는 고정 문자열 상수("다른 계정에서 실측해 그대로 박아넣은 값, 이 API는 공개 데이터라 무관하게 동작").
- **쿼리 파라미터**(Body 없음):

| 이름 | 값 예시 | 의미 |
|---|---|---|
| fhd_yyyy | 2026 | 연도(정수) |
| fhd_shtm | 2 | 학기(정수) |
| ic_kwa | `%` 또는 `B41005` | 전공 필터 없으면 `%`(전체), 있으면 `B41005` |
| ic_kwa_1 | 학과코드 | ic_kwa가 B41005일 때만 추가 |

- **응답 형식**: HTML. 페이지에 `content-type: text/html; charset=euc-kr (euc-kr임)` 이라고 명시.
- **응답 처리(파싱) 규칙**:
  1. 셀렉터 `tr[class^=tr_a]` 로 행 찾기 (tr_a0_chrm / tr_a1_chrm 줄무늬 클래스; 헤더 행 `tr_chrm_n`은 자연 제외).
  2. 각 행의 직계 자식 `> td` 가져오기. 14개 미만이면 행 버림.
  3. 14개 이상이면 인덱스별로:
     - 0: 정수 변환 = 일련번호 (변환 실패 시 행 버림)
     - 1: 마지막 `-` 기준 앞=과목코드, 뒤=분반. `-`가 없으면 전체가 과목코드, 분반은 빈 문자열
     - 2: 과목명
     - 3: 이수구분
     - 4: 실수 변환(실패 시 0.0) = 학점
     - 5: 대상학년
     - 6: 담당교수
     - 7: 시간표 원문 텍스트(요일/교시/강의실 뭉침; 요일별 세션 구조화는 별도 후속 파서 담당)
     - 8: 강의실
     - 9: 비어있지 않으면 폐강여부 true, 비면 false
     - 10: 정수(실패 시 0) = 정원
     - 11: 정수(실패 시 0) = 대기인원
     - 12: 수강신청비율(문자열 그대로, 페이지 예: `"30/40"`)
     - 13: 비고
  - 산출물: `[{일련번호, 과목코드, 분반, 과목명, 이수구분, 학점, 대상학년, 담당교수, 시간표원문, 강의실, 폐강여부, 정원, 대기인원, 수강신청비율, 비고}]`
- **응답 예시(발췌)**: 헤더 행 `<tr height="45" class="tr_chrm_n">`에 열 순서 순번/교과번호-분반/교과목명/이수구분/학점/학년/담당교수/강의시간/강의실/폐강여부/정원/예비수강신청인원/비율/비고. 데이터 행:
```html
<tr height="35" class="tr_a1_chrm">
 <td align="center">1</td>
 <td align="center">001022-01</td>
 <td align="left" ...><B>일본어회화</B></td>
 <td align="center">교선</td> <td align="center">2</td> <td align="center">1</td> ...
...
<td align="center"><font color="red"></font></td>          <!-- 폐강여부 -->
<td align="center"><B><font color="blue">30</font></B></td> <!-- 정원 -->
<td align="center"><B>5 </font></B></td>                    <!-- 예비수강신청인원 -->
<td align="center"><B>16.7% </font></B></td>                <!-- 비율 -->
<td align="left" ...></td>                                  <!-- 비고 -->
```
  (뒤쪽 행은 `tr_a0_chrm`; 페이지에 `<input type="hidden" name="ic_kwa_2">` 도 존재.)
- **특이사항/주의**:
  - 선행: www.daejin.ac.kr 로그인 성공으로 jsessionId, wmonid 확보 필요. userId2는 이 API에서 안 씀.
  - **모순**: 설명은 비율 예시를 `"30/40"`(분수)로 적었으나, 응답 예시의 비율 칸은 `16.7%`(퍼센트) 형태.
  - 응답 예시의 정원/예비수강 셀에 `</font>` 닫는 태그만 있는 깨진 HTML이 있음(셀 텍스트 trim 필요, 추정).
  - 학기 값 규칙: 이 API에는 명시 없음. 6번 페이지의 `selectYear` 옵션을 보면 학기 코드는 1, 11(여름), 2, 22(겨울)로 보임(추정, 6번 참고).
  - 노션 본문에 다른 노션 페이지(3d2e14ad4fe8...) 멘션 링크가 있음(내용은 미확인).

### 4. 시간표 - 강의계획서 목록 조회
- 노션: https://app.notion.com/9393c48d630d8333a87481991f89c935
- **메서드/주소**: `GET https://dreams2.daejin.ac.kr/sugang/center/Blsn020302.jsp?fhd_yyyy={연도}&fhd_shtm={학기}&ic_kwa={...}`
- **요청 헤더**: 3번과 동일 구성(페이지에 "course-catalog-spec.md와 동일한 쿠키 구성"이라고 적힘).
```
Cookie: JSESSIONID={jsessionId}; user_id=***; userId=***; nm=***; userFlag=***; userMjCd=***; resd1=***; resd2=***; orgCd=***; seq=***; wkkdCd=***; passwd=***; cookWebUser=***; WMONID={wmonid}
User-Agent: (3번과 동일)
```
- **요청 본문/쿼리 파라미터**(Body 없음). `ic_kwa`는 아래 5가지 중 하나만:

| ic_kwa | 추가 파라미터 | 의미 |
|---|---|---|
| B41001 | 없음 | 교필 |
| B41004 | 없음 | 교직 |
| B41020 | 없음 | 일선 |
| B41005 | `ic_kwa_1={학과코드}` | 해당 학과 전공(전필/전선/전기 섞여 나옴) |
| B41002 | `ic_kwa_2={교양영역코드}` | 해당 교양영역의 교양선택 |

  예: `fhd_yyyy=2026&fhd_shtm=2&ic_kwa=B41005&ic_kwa_1=AA0194%20` / `fhd_yyyy=2026&fhd_shtm=2&ic_kwa=B41002&ic_kwa_2=B42004`
- **응답 형식**: HTML. 메타 `charset=euc-kr` (응답 예시의 `<meta http-equiv="Content-Type" content="text/html; charset=euc-kr">`).
- **응답 처리(파싱) 규칙**:
  1. 셀렉터 `tr.tr_a_chrm` 로 행 찾기.
  2. 직계 자식 `> td` 가져오기. 2개 미만이면 행 버림.
  3. 1번 셀(인덱스 1) 안의 첫 `a` 요소 찾기. 없으면 행 버림.
  4. 그 `a`의 텍스트(trim) = "과목코드-분반" 키. 비어 있으면 행 버림.
  5. 그 `a`의 `href` = 상세 링크(도메인 없는 상대경로, `Blsn020303.jsp` 계열). 다음 API(5번)의 입력값.
  6. `{키: 상세링크}` 매핑을 모은 것이 이 호출 한 번의 결과.
  - 산출물: `{"과목코드-분반": "상세링크"}` (해당 카테고리 과목만).
- **응답 예시(발췌)**:
```html
<tr align="center" class="tr_a_chrm" height="26">
  <td >교필</td>
  <td ><a href="Blsn020303.jsp?fhd_00=922601&fhd_01=01&fhd_02=2026&fhd_03=2&fhd_04=2171008" target="RBF">922601-01</a></td>
  <td >2</td>
  <td align="left">&nbsp;&nbsp;<a href="Blsn020303.jsp?...같은 링크" target="RBF"><font color="red">AI시대의컴퓨팅사고</font></a></td>
  <td ><a href="...">담당교수명</a></td>
  <td align="left">&nbsp;수11:30-13:30</td>
</tr>
```
  헤더 행은 `tr_chrm1`, 열: 이수구분 / 교과번호-분반 / 학점 / 교과목명 / 담당교수 / 강의시간(학부).
- **특이사항/주의**:
  - 선행: 로그인으로 jsessionId, wmonid 확보.
  - 이 API는 "한 카테고리"만 조회. 전체 인덱스를 만들려면 교필/교직/일선 각 1회(3) + 학과코드 50개(50) + 교양영역코드 19개(19) = **총 72회** 호출 후 합쳐야 함(페이지 기재).
  - 학과코드 50개, 교양영역코드 19개의 실제 목록은 페이지에 없음. 예시값은 `AA0194%20`(공백 포함 인코딩), `B42004`.
  - 응답 예시 제목은 "응답예시"가 아니라 "[응담예시]"(오타).
  - 상세링크 쿼리: `fhd_00`=과목코드, `fhd_01`=분반, `fhd_02`=연도, `fhd_03`=학기, `fhd_04`=7자리 숫자(의미는 페이지에 없음).

### 5. 시간표 - 강의계획서 상세 조회

  - 페이지가 설명하는 구조(상세 로직은 "필요하면 요청"이라며 생략):
    - 셀 하나하나가 `<TL tid="..." to="세로위치" le="가로위치" ...>텍스트</TL>` 형태로 좌표를 가지고 나열됨.
    - 같은 `to`(세로위치)를 가진 셀들을 한 행으로 묶고 `le`(가로위치) 순으로 정렬하면 표가 재구성됨.
    - `tid` 값으로 셀 종류 구분(과목 표 셀, 졸업사정 기준표 셀, 안내문구 등).
    - `<HEAD>` 안에 스타일 정의(`<TA>` 폰트/색/굵기, `<LA>` 선 스타일, `<FA>` 배경색)가 있고 셀/선(`<LN>`)/사각형(`<RA>`)이 id로 참조.
    - 어떤 tid가 무슨 의미인지, 과목 한 줄 묶는 방법은 페이지에 **없음**.
  - 네트워크 실패는 별도 구분.
- **응답 예시(발췌, 개인 값 가림)**:
```xml

<INFORMATION><TITLE></TITLE><MRD>d_brsl122_01_rd.mrd</MRD>...</INFORMATION>
```

- **특이사항/주의**:
  - 선행: (1) 로그인으로 userId2 확보, (2) 7번 API로 `mrd_path`, `mrd_param` 확보. 7번 없이 이 API만으로는 데이터가 안 나옴.
  - `html5_uuid`는 매 호출 새 랜덤 UUID.
  - Content-Type에 `charset`이 붙지 않음에 주의(페이지가 명시).
  - 응답 예시의 HEAD `VALIST`의 `$6` 값이 학번이고, tid=5 셀에도 학번·학적(대학/학과/학년/재학 상태)이 들어있다 = 응답에 개인정보 포함. 예시에서는 가려서 옮김.
  - 응답 예시에 `<DSURL>`로 내부 IP 서버 주소가 노출되어 있음(참고).
  - MML 좌표계는 페이지 크기 `wd=8270, ht=11690`(A4 비례, 추정) 기준.
  - 응답 예시에 `<IM ... dt="data:image/bmp;base64,...">` 인라인 이미지가 있음(상세 용도 페이지에 없음).

## 페이지 간 모순/특이점 요약
1. 3번: 비율 설명 `"30/40"` vs 예시 `16.7%` 불일치.
2. 쿠키 구성이 API마다 다름: 3~5번(13개, 고정 상수 + JSESSIONID/WMONID), 6번(user_id/userId만 본인 userId2로 교체), 7~8번(userId + orgCd 2개만). `orgCd` 값은 3~8번 모두 같은 고정 상수.
3. 인코딩: 3·4·5번 euc-kr 명시/메타 확인, 6번은 명시 없음(별도 기록상 UTF-8이므로 일괄 EUC-KR 가정 금지), 8번은 XML `encoding="utf-8"`.
4. 호출 의존 관계: 4번 -> 5번(상세링크 resolve), 3번 <-> 6번(대조), 7번 -> 8번(mrd_path/mrd_param). 4번 전체 인덱스는 72회 호출.
5. 5번·8번은 세부 파싱 규칙(표별 파싱, MML tid 의미)이 페이지에 없고 "필요 시 별도 요청"으로 남겨져 있음.
